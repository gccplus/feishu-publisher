# 飞书统一链接与命名版本（0.1.18）

沿用 0.1.10 的飞书内容发布功能、协作者可管理权限，以及 0.1.16 的原文档更新能力。

## 安装与权限

解压 feishu-publisher-0.1.18.zip，用 main.js、manifest.json 替换仓库 .obsidian/plugins/feishu-publisher/ 下对应文件，保留 data.json，重新启用插件。

在飞书开放平台创建企业自建应用。在权限管理中开通以下**应用身份**权限，然后发布应用版本；组织可能需要管理员审核：

| 权限 | 用途 |
| --- | --- |
| `docx:document:create` | 创建主文档 |
| `docx:document:write_only` | 写入和更新正文块 |
| `docx:document.block:convert` | Markdown 转换 |
| `docs:document.media:upload` | 上传图片 |
| `docs:permission.member:create` | 添加可管理协作者 |
| `docs:permission.setting:write_only` | 可选，开启互联网只读分享 |

还需开通：

| 权限 | 用途 |
| --- | --- |
| `docx:document:readonly` | 读取待更新文档及正文块（0.1.16 已需要） |
| `drive:drive:version` | 查看、创建文档原生命名版本（0.1.17 新增） |

## 插件设置

1. App ID：应用的 `cli_...` 标识。
2. App Secret：在 Obsidian“设置 → 密钥库”创建密钥，保存应用 Secret；在插件设置中选中该密钥。
3. 飞书工作区：例如 `example.feishu.cn`，或该工作区内一篇文档的链接。
4. 协作者：你的飞书企业邮箱，或当前应用下的 Open ID（`ou_...`）；该账号会获得文档可管理权限。
5. 测试连接：检查应用凭证和 Markdown 转换。创建、上传、版本保存的实际权限会在发布时检查。

默认不打开互联网分享。需要时显式启用“发布后默认开启互联网只读”，或对已关联文档执行相应命令。

## 使用规则

笔记顶部写入：

```yaml
---
version: "1.0"
---
```

执行“发布当前笔记到飞书（统一链接与命名版本）”。首次创建文档，并保存命名版本“1.0”；自动写回 feishu_url，没有版本属性时默认为文本 "1.0"。

- 正文更新、version 不变：更新同一篇主文档，主链接不变；已有同名版本快照不覆盖、不重复创建。
- version 改为 "1.1"：更新同一篇主文档，保存命名版本“1.1”，主链接仍不变。
- 飞书文档右上角“... → 查看已存版本”可以查看对应版本快照。版本快照有独立查看链接，插件始终回写主文档链接。

命名版本是保存当时的快照：同版本后续修改只更新主文档，不会回写之前的同名快照。需要为新内容保存一个新的明确快照时，请改变 version。若调回已存在的版本名称，保留已有快照，主文档仍更新为本地内容。

日常仅需维护 version 和 feishu_url。版本信息从飞书版本列表读取；原 feishu_published_version 不再用于判断，并在发布成功后自动移除。

## 从旧版升级

已有 feishu_url 的笔记始终更新该链接，版本号改变也不另建文档。升级不会合并过去已经分开的多篇文档；以当前笔记 feishu_url 为主文档。若要指定更早的原文档，请先填写那个文档的主链接。

仍保留“将当前笔记发布为新的飞书文档”命令，仅在主动选择该命令时另建副本。

## 失败与权限

更新前检查版本列表访问权限。权限不足、文档失效时停止，不自动新建替代文档。新建后版本保存失败时保留待完成链接，重试优先继续该篇文档。

版本创建为异步操作，插件提交一次后查询确认。返回版本标识但未及时确认时，会记录 feishu_pending_snapshot；重试先查询已提交的标识，避免重复创建版本。网络中断且未取得版本标识时，需先在飞书核对：若已存同名版本，再次发布可自动识别；若确实没有，确认后删除 feishu_pending_snapshot 属性再重试。飞书明确返回权限等拒绝错误时，修正权限即可重试。

成功发布后会清理待完成属性。正文已更新但命名版本未确认时，结果会明确提示，不能视为整次版本发布完成。

更新仍是本地覆盖飞书正文，不是双向同步；块关联评论可能受影响，避免发布期间同时编辑。命名版本与历史记录不同，本插件未增加一键回退；还原飞书内容后，本地不会跟着还原。

## 保留的发布行为

协作者继续授予 full_access 可管理权限；应用仍为所有者。图片、Callout、Mermaid 使用原飞书发布方式。同版本和跨版本更新保留主文档分享设置；默认互联网只读仅在新建主文档时设置。
